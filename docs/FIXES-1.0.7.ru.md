# Исправление первого запуска в NetPulse 1.0.7

На новой установке 1.0.6 пустой список `PreviousInstallDirs` мог читаться из
Windows REG_MULTI_SZ как один пустой элемент. Добавление `data/<SID>` к этому
элементу создавало относительный путь. При запуске из папки приложения он
указывал на текущий профиль: клиент брал блокировку как для прежнего профиля,
а затем пытался повторно заблокировать тот же файл как текущий профиль.
Отсюда сообщение «уже работает» даже при отсутствии второго процесса.

В 1.0.7 история принимает только абсолютные локальные пути. Текущий профиль
и повторяющиеся пути исключаются из миграции. При пустой истории установщик
удаляет значение реестра; клиент также корректно читает старую ошибочную запись.
Блокировка действующего экземпляра сохраняется, а недоступная папка или
неправильный тип файла блокировки получают отдельное сообщение.

Команда `NetPulse.exe --startup-check` проходит тот же путь подготовки
профиля и блокировки, что обычный запуск, и завершает работу до запуска
сетевого контроллера. В тестах используется отдельная копия приложения
и тестовые данные; работающий клиент проверяется только в изолированном режиме.

Обновление выполняется поверх установленного клиента. Удалять подписки,
папку `data` или рабочие файлы блокировки вручную не требуется.
