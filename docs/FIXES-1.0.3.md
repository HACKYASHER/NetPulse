# Журнал и IPv6 — 1.0.3 beta

Присланный журнал: 91 ошибка — 66 тайм-аутов direct, 23 недоступных IPv6-маршрута, 2 обрыва HTTP/2 DNS. Признаков падения клиента в этом фрагменте нет. Прочитаны настройки и таблица маршрутов без изменения пользовательской сети: включён выборочный VPN, а у физического Ethernet нет IPv6-маршрута по умолчанию.

Исправлена настройка уровня журнала: ранее оба ядра принудительно запускались только с предупреждениями, несмотря на сохранённый INFO. Теперь INFO показывает обычные соединения. Выбор уровня находится в Активности; смена уровня при активном VPN проверяет и перезапускает соединение с сохранением отката.

При смене категории сбрасывается горизонтальная прокрутка. Загрузка даты откладывается до завершения обновления списка. Ошибка чтения отличается от пустого журнала. Читатель учитывает ротации, сохраняя лимит 500 строк и 256 КиБ на запрос.

В Сеть → Подключение добавлен IPv6 в TUN. Авто выбирает IPv4 для выборочного/прямого режима, если физический интерфейс заведомо не имеет IPv6-маршрута; неизвестное состояние не трактуется как отсутствие IPv6. Глобальный VPN и принудительное IPv4 и IPv6 сохраняют доступ через сервер. При необходимости IPv6 через VPN-сервер выберите IPv4 и IPv6 явно. Только IPv4 ограничивает TUN и DNS; изменения не отключают IPv6 в Windows или на других адаптерах.

IPv6-адреса TUN задаются параметром address, а стратегия DNS управляет разрешением имён: [TUN](https://sing-box.sagernet.org/configuration/inbound/tun/), [DNS](https://sing-box.sagernet.org/configuration/dns/). Конфигурации проверены реальным комплектным ядром.

Тайм-ауты внешних адресов и периодических попыток подключения к другой локальной подсети сохраняются в журнале. Они требуют доступного адреса и подходящего маршрута; исправление журнала не делает недоступный узел доступным. Доменные маршруты и список приложений пользователя автоматически не менялись.
