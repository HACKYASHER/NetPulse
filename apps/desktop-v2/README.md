# NetPulse 3.0.4

Исправления MTU, каталога приложений, подсказок и обслуживания службы.

- Playground: отдельный поиск процессов по EXE/пути/PID до запуска наблюдения и фильтр собранных соединений по адресу/домену/PID/протоколу/маршруту. Интервал выровнен с кнопками.
- Игровой пресет сохраняет выбранный System Proxy. Публичный loopback-прокси не требует пароль при TUN; закрытые диагностические порты сохраняют авторизацию. Правила приложений не меняются.
- MTU снова предлагает расчётный кандидат при включённом TUN или фильтрации ICMP: MTU активного физического адаптера минус 80, в пределах 1280–1420. Это эвристика, а не измеренный оптимум. Если DF-измерение удалось, оно показывается отдельно.
- Каталог хранится в applications.json в каталоге данных клиента. При первом запуске переносится прежний локальный список; выбранные правила остаются в настройках. Запись атомарная, одинаковые пути объединяются, версии известных установок собраны в одну строку. Разные Node/EXE по разным путям не смешиваются. Каталог не входит в старый формат резервной копии; выбранные пути входят.
- Исправлены ширина ввода ключа, поля поиска, значки вида списка и кнопки выбора ядра. Возле каждого EXE вопрос больше не показывается.
- Клики, ввод и переходы больше не записываются в журналы; реальные ошибки интерфейса сохраняются. Предупреждения Xray распознаются по полю уровня, вывод ядра сохраняется целыми строками.
- На физическом интерфейсе без IPv6 default route прямое подключение по доменному имени использует IPv4. Явные IPv6-адреса и собственный DNS приложения этим не преобразуются; IPv6 внутри VPN остаётся доступным.
- Установщик закрывает GUI штатной проверкой и останавливает свою службу до замены файлов и перед старым деинсталлятором. Нужен UAC; при неподтверждённой остановке операция прерывается до копирования. Удаление также останавливает службу.


- Служба обрабатывает запросы независимо; ожидания IPC и завершения ядра ограничены. Повторная проверка потери маршрутов отделена от краткого сбоя чтения Windows.
- «Восстановить службу (UAC)» доступно при таймауте даже с незавершённой сессией. После проверки регистрации, владельца и фактического пути можно завершить только собственную зависшую службу. Пользовательское подтверждение Windows требуется.
- Сеть → TLS: общие настройки SNI/Host/uTLS без выбора профиля. Сохраняются общей кнопкой; несовместимая настройка отклоняется до переключения.
- Playground: кнопка обновления, автоматическое обновление по желанию с паузой 1/5/10 секунд, без параллельных запросов.
- Подсказки «?» возле полей и переключателей доступны мышью и с клавиатуры.
- Подписки показывают трафик и срок из Subscription-Userinfo. Если данных нет, значение неизвестно. Срок отдельного UUID/ключа невозможно достоверно вывести из его текста.
- JSON каждого сервера редактируется как исходящий объект NetPulse/sing-box (до 64 КиБ), со строгой схемой и проверкой ядром. Изменения хранятся отдельно от исходного ключа, шифруются DPAPI, сохраняются при обновлении неизменившегося ключа.
- В настройках подписки можно навсегда запретить ручное редактирование конфигураций. Запрет сохраняется после обновления и восстановления старого бэкапа. Это локальное правило клиента, не DRM от владельца компьютера.
- В обзоре доступен выбор транспортного ядра с немедленным применением.
- Основной журнал не показывает рутинные Command Started/Succeeded; категории ядра и службы получают жизненный цикл и диагностические сообщения.
- MTU: измерение DF с повторным подтверждением; при невозможности — отдельно помеченная оценка по активному физическому адаптеру. Неактивные адаптеры скрыты; есть кнопка показа.

Физический TUN, установка с UAC и поведение конкретного игрового сервера требуют проверки на устройстве. Изменения исправляют найденные пути блокировки восстановления; точная причина первоначального разрыва пользователя пока не воспроизведена.

# NetPulse 3.0.1

Локальный Windows-клиент для ваших VPN-серверов. Полный исходный код и релизы: https://github.com/HACKYASHER/NetPulse

Серверы сгруппированы по раскрывающимся подпискам с меню обновления, проверки пинга и редактирования названия, интервала обновления и защиты ссылки. Правая панель подключения убрана. Доступны виды «Список» и «Значки». Идентификатор данных и внутренний ключ установщика сохранены для обновления версии 2.x без отдельного профиля Windows.

## Сеть (отдельный пункт слева)

- **Общее:** MTU, пресеты, служба и проверочный адрес. DNS вынесен в собственную вкладку. «Игры — TUN» включает TUN, выбирает DoH Cloudflare через VPN и сохраняет выбранный System Proxy, MTU и правила приложений. Это настройка совместимости; она не переключает белый список на весь трафик.
- **TLS и транспорт:** выберите профиль, настройте SNI, HTTP Host для WebSocket/XHTTP и uTLS. Переопределения хранятся с защищённым профилем, не меняют исходную запись подписки и сохраняются при обновлении неизменённого сервера и резервном копировании. Применение активного профиля переподключает VPN. Отключение SNI доступно с sing-box без Reality; проверка сертификатов остаётся включённой.
- **Фрагментация Xray:** выключена по умолчанию. Доступны tlshello / первые три записи TCP, диапазоны длины, интервала и maxSplit. Ядро выбирает значения в диапазонах. Фрагментируется внешний транспорт к VPN-серверу. Для Hysteria2/QUIC функция недоступна.
- **Mux/XUDP:** выключен по умолчанию. Поддерживаются VLESS/Trojan TCP и WebSocket без Vision. gRPC/XHTTP используют свой транспорт. Настройка UDP 443: вне Mux, разрешить внутри Mux или отклонять. Mux может ухудшить скорость больших загрузок.
- **Правила:** до 64 упорядоченных правил domain, IP/CIDR, GeoIP, Geosite и EXE; действия VPN / напрямую / блокировать. Приоритет: перехват DNS, прежние доменные исключения, новые правила, общий список приложений. GeoIP применяется после разрешения адреса. Только выбранные наборы SagerNet загружаются по HTTPS из официальных репозиториев sing-geoip / sing-geosite; обновление ядром раз в сутки, максимум восемь наборов. Доступность и точность внешних наборов не гарантируются. Правила включены в импорт/экспорт маршрутизации.
- **Fake IP:** выключен по умолчанию, применяется только с TUN. Сопоставление DNS хранится в памяти, диапазоны 198.18.0.0/15 и fc00::/18. Доменные исключения получают реальные ответы. После переключения заново откройте соединения приложений: их DNS-кеш может сохранять старый адрес.
- **DNS:** TCP/UDP 53 перехватываются внутри захваченного трафика. Для зашифрованного upstream выберите DoH или DoT. Собственный DoH приложения не перехватывается этим правилом. Возможны исключения EXE из HTTP/TLS/QUIC-сниффинга; они не меняют TLS приложения.
- **Playground:** выберите работающий процесс или все соединения ядра и запустите наблюдение. Windows даёт TCP-состояния и локальные UDP-сокеты; ядро добавляет адрес, маршрут и байты захваченного трафика. До 300 записей в памяти, ручное обновление по умолчанию; можно включить интервал 1/5/10 секунд. Отдельной базы и драйвера нет. Опрос прекращается при остановке или уходе из раздела. PID Windows и сведения ядра могут отличаться по полноте; закрытые короткие соединения между опросами могут быть пропущены. Предупреждения ядра могут относиться к другим приложениям. Содержимое HTTPS и внутренние ошибки чужих программ не читаются.

## Журналы

В «Активности» доступны журналы: основной, ядро, туннель, подписки, служба. Файлы JSONL находятся в каталоге данных `logs/ГГГГ-ММ-ДД/` по локальной дате. Основной журнал содержит значимые операции и ошибки; обычные клики, ввод, навигация и начало/конец каждого опроса не записываются. Вывод ошибок ядра предварительно скрывает данные профиля и пароли. UI показывает последние 500 строк (до 256 КиБ), окрашивает уровни и позволяет копировать записи. Автопрокрутка включена при первой установке, запоминает выбор и обновляет журнал раз в две секунды. Можно очистить все разделы за все даты; новые действия продолжат записываться. Общий лимит архива 128 МиБ; при переполнении удаляются самые старые управляемые файлы. Файлы версии 2.x остаются в корне logs.

## Практические ограничения

uTLS использует реализации комплектных ядер и меняет только внешний ClientHello VPN-соединения. JA4 и JA4H — вычисляемые свойства TLS/HTTP; точное соответствие актуальному Chrome/WinHTTP не заявляется. TLS игры, её HTTP внутри HTTPS и сертификаты не подменяются. Произвольное добавление байтов в заголовки TLS не реализовано: оно может повредить соединение. Браузерный padding определяется выбранным профилем uTLS, отдельного управления padding нет.

В 3.0 не входят фоновая имитация посещения сторонних сайтов, объединение нескольких интернет-каналов, выбор отдельной ноды для каждого игрового адреса, разные транспортные профили VPN для каждого процесса и бесшовный перенос существующих игровых сессий между серверами. Для части этих функций нужны изменения архитектуры и поддержка сервера. Имеющееся автоматическое переключение меняет сервер после трёх неудачных проверок; текущие TCP/игровые сессии могут оборваться. Фрагментация не гарантирует обход DPI или рост скорости.

Для переносной версии службу TUN нужно установить/обновить в «Сеть». Установщик делает это через обычный запрос UAC. Завершите старый NetPulse через «Выход» перед обновлением. EXE не подписаны. Требуется Windows x64 и Microsoft WebView2 Runtime; установщик проверяет WebView2, приложение не требует отдельно установленного Visual C++ Runtime.

Разработано HACKYASHER совместно с OpenAI Codex. Сведения о лицензиях — в LICENSE-NOTICE.md; ручные проверки Windows — в WINDOWS-CHECK.md в публичном репозитории.


## Запуск, обновления и защита

Проверка и подготовка ядер выполняются в фоне. При отсутствующем или заблокированном компоненте интерфейс, настройки и журналы остаются доступны; сообщение указывает на недоступный компонент. Неустранимая ошибка запуска показывается отдельным сообщением и сохраняется в startup-error.txt. Если работает старая версия, клиент сообщает об этом.

Проверка релизов GitHub выполняется через 5 секунд после запуска и раз в 6 часов отдельным native worker, включая автозапуск в трей. Загрузка и установка выполняются по команде пользователя. Подписки обновляются по своему интервалу; неудачные запросы повторяются не чаще раза в 15 минут. Загрузка подписок в фоне не удерживает блокировку подключения.

Установщик NetPulse 3.0.1 распознаёт прежнюю установку и предлагает обновление/восстановление с сохранением данных, удаление или выход без изменений. После копирования проверяются ядра; отсутствие или изменение компонента не считается успешной установкой. Для старых установок сохранены внутренний ключ реестра и каталог данных, для новых используется название NetPulse.

Официальные ядра проверяются по SHA-256; отдельные zapret/WinDivert64.sys в поставку не входят. Это проверка происхождения и целостности, а не обещание отсутствия обнаружений: Kaspersky может классифицировать легальные прокси-инструменты как Riskware. Приложение и установщик пока не подписаны сертификатом издателя. Исключения и отключение защиты автоматически не добавляются. [Что означает Riskware](https://threats.kaspersky.com/en/class/Riskware/).


## Стабильность 3.0.4

Статистика ядра читается отдельно от команд подключения: фоновые запросы объединяются с интервалом не менее пяти секунд. Последние успешные значения сохраняются при недоступности API с явной пометкой. Монитор только читает соединения и никогда не вызывает их массовое закрытие. Таймаут службы помечает состояние как неподтверждённое; после здорового ответа предупреждение снимается.

Новый сервер или ядро предварительно проверяется на отдельных локальных портах до остановки действующей сессии. Отказ кандидата сохраняет текущий процесс; успешная смена всё равно обрывает старые TCP-сессии. Ошибка проверки содержит короткое сообщение, подробности доступны в журнале ядра.

Прямой резолвер предпочитает IPv4 без удаления IPv6-only ответов. Буквальный IPv6 или IPv6-only домен в прямом маршруте требует IPv6 от физической сети; преобразование в IPv4 и скрытое перенаправление в VPN не выполняются.
